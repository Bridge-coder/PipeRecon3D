## 4. 执行顺序和命令（确认后才运行；一次只跑一个重任务）

### 4.1 Windows 侧：建发行版（我运行）

```powershell
wsl --install Ubuntu-24.04 --name pipe3d --location D:\wsl\pipe3d --no-launch
wsl --manage pipe3d --set-sparse true
```

### 4.2 第一次启动：需要你自己做（约 1 分钟）

```powershell
wsl -d pipe3d
```

Ubuntu 第一次启动会让你**设置一个 Linux 用户名和密码**。这一步请你自己输入（我不替你创建账户、不输入密码）。设好后输入 `exit` 退出即可。
之后我的命令都用 `wsl -d pipe3d -u root -- ...` 执行，不需要密码。

### 4.3 发行版内：系统包和 CUDA（我运行，root）

```bash
apt-get update
apt-get install -y --no-install-recommends build-essential python3-dev python3-venv git ninja-build wget ca-certificates
wget -P /tmp https://developer.download.nvidia.com/compute/cuda/repos/wsl-ubuntu/x86_64/cuda-keyring_1.1-1_all.deb

apt-get clean                             # 删掉 3.6 GB 的 deb 缓存
/usr/local/cuda-12.8/bin/nvcc --version   # 检查：应显示 release 12.8
```

### 4.4 Python 环境（我运行）

```bash

/opt/gsenv/bin/pip install torch==2.9.1 torchvision==0.24.1

# 检查：2.9.1 12.8 NVIDIA GeForce RTX 5060 Ti (12, 0)
```

### 4.5 编译 gsplat 和 fused-ssim（我运行；CPU 重任务，单独跑，预计十几到几十分钟）

```bash
git clone https://github.com/nerfstudio-project/gsplat.git /opt/src/gsplat
git -C /opt/src/gsplat checkout 512d366b6707
git -C /opt/src/gsplat submodule update --init gsplat/cuda/csrc/third_party/glm
export CUDA_HOME=/usr/local/cuda-12.8 PATH=/usr/local/cuda-12.8/bin:$PATH TORCH_CUDA_ARCH_LIST="12.0" MAX_JOBS=4
/opt/gsenv/bin/pip install --no-build-isolation -v /opt/src/gsplat
/opt/gsenv/bin/pip install --no-build-isolation "git+https://github.com/rahul-goel/fused-ssim@a7c48d6dd7ac6dc39a7958c7c4452e0b10418f38"
/opt/gsenv/bin/pip cache purge            # 删掉约 4 GB 的 pip 下载缓存
```

- `TORCH_CUDA_ARCH_LIST="12.0"`：只为本机显卡编译，编译最快。
- `MAX_JOBS=4`：每个 nvcc 进程要 1–1.5 GB 内存，WSL 默认只有 8 GB，并行太多会内存不足。

### 4.6 冒烟测试（环境装好后，再单独给你看一次命令）

目的：确认 gsplat 能在这块显卡上用我们的真实帧训练，量出显存和速度，作为后面每一步耗时的依据。脚本已写好（10-20），**未运行**。

**① Windows 侧导出**（仓库根目录，现有 Python；轻任务，约 1 分钟）

```bash
python -I pipesplat/export_scene.py D:/pipe3d/concrete_2 "C:/Users/PC/Desktop/运动估计三维重建/data/sheffield_concrete_5m/300mm_concrete_5meters_ON_2lm_2u_CLOSED_2.mp4" D:/pipe3d_gs/smoke --frames 30 --held 5 --at 0.5 --ahead 1.5
```

- 取管道中段**连续 30 张建模帧**（每 5 个视频帧一张，约 150 个视频帧、6 秒、约 27 cm 行程），读**原始视频帧**（不做 CLAHE，和 lampmap 比较用的是同一种帧）；
- 另取 5 张**留出帧**（两张建模帧正中间的视频帧，没参与 SfM/稠密/贴图），位姿按 lampmap 的方法插值；
- 位姿从管道坐标（米）换成 OpenCV 相机矩阵；内参 f、主点、k1 照抄 SfM 注册值（主点按 gsplat 的像素中心约定加 0.5）；
- 初始化点 = 第一台相机后 5 cm 到最后一台相机前 1.5 m 之间、有贴图的 OpenMVS 网格面（面中心、该处贴图颜色、面法向、面大小）。
- 输出 `D:\pipe3d_gs\smoke\scene.npz`（约几十 MB）+ `scene.json`。

**② WSL 侧训练**（GPU 任务，单独跑；预计几分钟，以实测为准）

```bash
wsl -d pipe3d -u root -- /opt/gsenv/bin/python /mnt/c/Users/PC/Desktop/PipeRecon3D/pipesplat/smoke.py /mnt/d/pipe3d_gs/smoke --iters 2000
wsl -d pipe3d -u root -- /opt/gsenv/bin/python /mnt/c/Users/PC/Desktop/PipeRecon3D/pipesplat/smoke.py /mnt/d/pipe3d_gs/smoke --iters 2000 --no-ut
```

- 故意最简：不加灯光模型、不加深度损失、不加致密化、不修位姿（那些是第 1–4 步）。每个网格面一个高斯；尺度取"到最近相机的距离 / 焦距"（Gaussian-LIC2 7.1.1）和"面大小的一半"中较大的那个（我们的点是相隔几毫米的网格面，不是稠密激光点，只用前者会有空洞）；不透明度 0.1；损失 0.8·L1 + 0.2·D-SSIM（Gaussian-LIC2 式 21）。
- 第一次运行用 3DGUT 直接渲染原始畸变帧（k1 = −0.33）。k1 < 0 时径向模型在 r_u = 1/√(−3·k1) 之外会"折回"，相机旁边的管壁会被第二次投进画面，所以每次渲染前去掉超过该半径 95 % 的高斯（它们本来就在画面外）。
- 第二次加 `--no-ut`：忽略畸变、按针孔渲染，**只用来检验畸变约定对不对**。
- 输出（在 `D:\pipe3d_gs\smoke\`）：`smoke.json` / `smoke_no_ut.json`（高斯数、每秒迭代数、显存峰值、训练前后 PSNR）、`smoke_loss.csv`、三联图 `smoke_<train|held>_<帧号>.png`（视频帧 | 渲染 | 差值×4）。

**通过标准**
1. 不报错，显存峰值（reserved）< 8 GB；
2. 5 张留出帧的 PSNR 训练后高于训练前，三联图里管壁接缝、纹理和视频帧对得上（差值图里没有整体错位的双边）；
3. 3DGUT 那次的留出帧 PSNR **不低于** `--no-ut` 那次——否则说明 k1 的约定传错了，要先查清再做第 1 步。

注意：这里的 PSNR 没做每帧增益匹配、也只看 5 张帧，**不能和 lampmap 的 29.82 dB 比**；正式对比在第 1 步用 44 张留出帧和同一套指标做。

### 4.7 冒烟测试结果（2026-10-20，用户同意后运行）

- 导出：第一次因 `cv2.remap` 不接受宽于 32767 的映射而报错（47 万个点排成一行），改成 numpy 双线性取色后通过。
  窗口 = 源帧 1020–1175 的 30 张建模帧（相机 x ≈ 1.99–2.36 m；1080→1095 之间有 2 帧未注册），留出帧 1022、1057、1107、1137、1172；初始化点 477,058 个网格面（面中位大小 1.6 mm，x 1.94–3.86 m）；`scene.npz` 33 MB，用时 44 s。
- 训练（各 2000 次迭代，先后各跑一次）：

| | 3DGUT（k1 = −0.33） | `--no-ut`（针孔） |
|---|---|---|
| 用时 / 速度 | 25.1 s / 79.6 次每秒 | 22.9 s / 87.3 次每秒 |
| 显存峰值（reserved） | 459 MB | 434 MB |
| 建模帧 PSNR 中位（前 → 后） | 23.95 → 33.35 dB | 23.99 → 33.30 dB |
| 留出帧 PSNR 中位（前 → 后） | 23.89 → **33.01** dB | 24.10 → **33.25** dB |
| 留出帧：错位 shift_px | 1.51 | 1.45 |
| 留出帧：细节相关 detail_corr | **0.495** | 0.356 |
| 留出帧：高频残差 mse_high | **18.5** | 20.3 |
| 留出帧：低频残差 mse_low | 9.4 | **4.9** |
| 留出帧：细节能量比 hf_ratio | 0.085 | 0.055 |

（后五行用 `lampmap/imgmetrics.py` 在三联图上算，整幅画面，无增益匹配。）

- **标准 1（不报错、显存 < 8 GB）**：通过。显存只用了 0.46 GB，速度约 80 次/秒（47.7 万个高斯，768×548）。
- **标准 2（留出帧 PSNR 上升、位置对得上）**：通过。三联图里管壁、管底两条线、透视都和视频帧重合；误差最大处是远端端盖的金属反光环（镜面反光，静态高斯表达不了）和近处被车灯照亮的管底。
- **标准 3（3DGUT 的留出帧 PSNR 不低于 `--no-ut`）**：**按字面没通过**（33.01 < 33.25），但事后证明**这条标准本身不成立**：
  - 两次训练前的 PSNR 就几乎一样（23.89 / 24.10），而针孔模型在画面边缘错几十像素——说明在这种暗、平滑的管壁画面上 **PSNR 对几何错误不敏感**，训练中高斯还会挪位置、改颜色去"凑"图像。
  - 改用直接的几何检验 `pipesplat/setup/check_distortion.py`（单个微小高斯放在已知相机坐标，比较渲染位置和 OpenMVG 公式 x_d = x_u(1 + k1·r²) 的预期像素）：**3DGUT 在 6 个画面内的点上误差全部 0.00 px**；针孔投影和畸变模型的位置相差 2–36 px（越靠边越大，画面四角估计上百像素）。所以 k1 约定和主点 +0.5 都传对了。
  - 细节指标也支持 3DGUT：细节相关 0.495 对 0.356、高频残差 18.5 对 20.3；3DGUT 的 PSNR 略低全部来自低频明暗（mse_low 9.4 对 4.9，主要是帧 1107 近处管底 29.3），这正是第 2 步灯光模型要解决的。

**对第 1 步的三条启示**（都来自上面的实测）：
1. 不能只看 PSNR：几何错几十像素的模型 PSNR 照样 33 dB。第 1 步必须同时报错位、细节相关、低频/高频残差和整段留出测试（docs/06 第 6 节已有，现在有了实测依据）。
2. 即使在 37 cm 的小窗口里，剩下的差距也主要是低频明暗——支持第 2 步。
3. 渲染的细节能量只有视频的 5–14 %：每个网格面一个高斯（1.6 mm，在 0.3 m 处约 4 px）、不加密、只训 2000 次，表达不了像素级细节。第 1 步需要更密的初始化或致密化（Gaussian-LIC2 不用 ADC 是因为增量建图，离线时可以用）和更多迭代；按 80 次/秒估算，3 万次迭代约 6–7 分钟，整段 concrete_2（约 140 万个面）约 3 倍时间、显存约 1.5 GB，都在本机能力内。
