## 2. 准备工作（两段视频各遇到一个新情况）

**A：计数器读数。** 照明更亮后，计数器字形被背景"污染"，字形聚类出了 1016 类（暗视频只有十几类）。
给 `evaluate.py counter` 加了 `--nearest`：只给 41 个大类标数字，其余类取最近的已标类；再用"计数器只增不减"做清理
（偏离 51 帧滑动中位数 > 0.1 m 的读数换成中位数，64 处，然后强制单调）。结果 0.00 → 14.01 m，单调，步长 0.01–0.25 m。

**B：换相机。** 新增 `vision/calibrate_checkerboard.py`：
- 标定视频是同一 PAL 画面放大 1.25 倍嵌在 1280×720 里（左边 190 px 黑边），所以先裁出 900×720、缩放到 720×576，在 Pipe1 自己的像素里标定；
- 211 帧检测到 9×6 棋盘格，取 60 帧标定：**重投影 RMS 0.35 px**，f ≈ 490 px（广角），k1 = −0.248；
- 像素不是正方形（fy/fx = 1.016），按 1.0159 横向拉伸后用单焦距模型（与 OpenMVG 的相机模型一致）；
- 画面中下方烧录的距离文字会变成"不动的特征点"，用 `--crop 0 0 720 490` 裁掉。

```bash
python scripts/vision/calibrate_checkerboard.py "Calibration Checkerboard.mp4" camera.json --pattern 9 6 --crop 190 0 1090 720 --resize 720 576
python scripts/reconstruct_video.py Pipe1.avi WORK --every 1 --last 700 --plain --crop 0 0 720 490 --stretch-x 1.0159 \
       --focal 489.7 --cx 332.4 --cy 264.5 --k1 -0.2477
python scripts/reconstruct_video.py 300mm_mix_15meters_ON_3lm_3u_CLOSED_1_stop_at_14meters.mp4 WORK --every 3 --last 1350
```

B 的三维视图和对比视频另需两个设置（原因见第 4 节）：管径用真值定尺度后推出的 435 mm（与 Pipe 1 视频独立核实的 420–465 mm 一致，见第 3 节说明），管道坐标逐段校正：

```bash
PIPE3D_PIPE_DIAMETER_M=0.435 python scripts/reconstruct_video.py Pipe1.avi WORK --skip-recon --plain --crop 0 0 720 490 --stretch-x 1.0159 --straighten
```

说明：
- "定位误差"与文献评估单目视觉里程计（如 ORB-SLAM3）的方式一致：单目没有尺度，用真值对齐一个全局尺度后看位置误差。
  真值有 0.1 m 的刻度，所以误差曲线呈台阶状；计数器在机器人起步时停在 0（前 155 帧），按 `evaluate.py` 的惯例只评估 0.25 m 之后。
- B 的尺度在第一个 2 m 偏大 11%、最后 2 m 偏小 10%，这是单目重建常见的局部尺度起伏；在 Sheffield 实验管上是 ±5%。
  需要更稳的尺度时，可用管径逐段修正（`evaluate.py` 已实现）或融合编码器/IMU。
- 管径推断方法在 A 上与标称值相差 3%。B 的 435 mm 与 Edwards 等 2023 原文的"Pipe 1 约 600 mm"相差 27%，于是在 Pipe 1 视频本身上做了核实（docs/03 第 4 节）：
  视频末尾云台转动的纯旋转段直接测出 f ≈ 540 px（标定值 490 px，"600 mm"需要的 380 px 被排除），管壁特征随线缆里程的扫动给出 f × 半径 ≈ 115 px·m，
  线缆里程与检查井 GPS 相比只会偏长。合起来 Pipe 1 内径约 420–465 mm（最可能 450 mm 标准管），**标定焦距没有错，模型不需要重跑**。

**A**：两节混凝土管和 2.1 m 处的管节接口清楚；管内视角与同一位置的视频帧一一对应（划痕、污迹位置一致）。4.6 m 以后是检查井入口，那里有破面和飞片，不在两节混凝土管的范围内。

**B**：管顶和两侧管壁连续，管节接口看得出来（模型坐标约 2.7、5.6、8.3 m）。**管底有流动的水和沉积物**：水面在动、会反光，相邻帧之间找不到一致的深度，
所以下半周大片缺失，并留下伸向管内的飞片。这是真实污水管与实验管最大的差别，也是这套纯视觉方法目前的边界（改进方向见 README 第 6 节）。
画面四角约 11% 在模型图里是空白：这台广角相机的单参数畸变模型（k1 = −0.248）只覆盖到归一化半径 0.775，画面四角在 0.97，模型够不到。

**为 B 改的代码**（默认行为不变；在 Sheffield 的 concrete_2 和 A 上核对过，修改不触发、结果逐位相同）：

1. `evaluate.pipe_frame`：整段 10 m 的污水管不是一根直圆柱，全局圆柱拟合得到半径 31 个单位（约 3.9 m）、相机离"管轴" 2.2 m 的错误结果，模型全长只有 6.5 m。
   现在只要相机落在拟合圆柱之外，就改用相机轨迹作管轴、分段拟合半径。改后全长 10.7 m（真值 10.6 m）。
2. `render_views.py` / `video_compare.py` 加 `--straighten`：单段模型也逐段校正中心和尺度（原来只对分段拼接的模型这样做）。
   不加时管道的轻微弯曲会被画成"管壁偏差"。加后相机位置与真值相差的中位数从 7.4 cm 降到 3.4 cm。
3. `video_compare.py` 加 `--plain --crop --stretch-x`：原来把所有 720×576 的视频都当作 Sheffield 视频裁剪（Pipe1 正好也是 720×576），左边的原始帧会与模型对不上。
   `reconstruct_video.py` 现在把这三个参数和 `--straighten` 一起传过去。
4. `render_views.undistort_grid`：广角镜头下，画面四角的畸变反解会发散（第一次运行因此申请 10.6 PiB 内存而退出）。现在模型够不到的像素留空白；
   Sheffield 相机的画面四角在可解范围内（0.60 < 0.64），输出与原来逐位相同。
