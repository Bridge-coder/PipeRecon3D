# 06 改进方案：对照 Gaussian-LIC2，让管道重建的画面更还原、更清晰

日期：2026-10-19。状态：**方案，未执行**。
对照对象：Lang 等，Gaussian-LIC2: LiDAR-Inertial-Camera Gaussian Splatting SLAM，IJRR 2026（arXiv 2507.04004v3，代码 github.com/APRIL-ZJU/Gaussian-LIC）。

本文的推理顺序：先用实测数字说清楚**我们的模型现在差在哪**（第 2 节），再把 Gaussian-LIC2 的每个部件拿来问一句"它能不能补上其中某个差距"（第 3 节），
再看更新的模型里有没有更对口的（第 4 节），最后把能用的部分排成先后有依据的步骤（第 5 节）。每个改动都写明针对哪个差距、怎么验收、不通过怎么办。

---

## 0. 结论

1. **Gaussian-LIC2 不能整套搬过来**，原因有三个，都可以核实：
   - 它要求激光雷达 + IMU + 相机同时存在。我们 5 组数据里只有 InPipe 172011 满足；Sheffield 混凝土管、实验室管 A、真实污水管 Pipe 1 只有视频，根本跑不了。
   - 它假设光照是静止的（户外日光），只用 D-SSIM 损失去抵抗曝光变化。管道里唯一的光源是跟着相机走的车灯，同一块管壁离相机越近越亮。我们已经实测：留出帧误差的 68–93 % 是这种平滑明暗（灯光图实验）。
   - 它的激光里程计在"结构单一"的场景会退化（论文表 2：4 条退化序列上只用激光+IMU 时漂移 6.6–13.7 m），而直管正是沿管轴退化的典型场景（我们 F3 的 ICP 在管轴方向解出 54–150 mm 乱跳）。
2. **它有三个部件正好对上我们的差距，可以借用**：
   ① 用所有建模帧联合优化的高斯外观模型（取代 OpenMVS 每个面只挑一帧贴图）；
   ② 用激光深度约束高斯几何（他们的实验：去掉深度约束后，光度定位从 0.03 m 漂到 7.12 m）；
   ③ 用渲染图和原图的光度差反过来修正每帧相机位姿（他们的 c2 相机因子）。
3. **必须补上它没有的东西**：管内车灯的物理模型（光强 ∝ 1/距离² × 入射角余弦 × 灯的角度分布 × 暗角 × 每帧曝光）。
   依据是我们自己的灯光图实验，以及内窥镜领域同类问题的论文（LightNeuS、PR-ENDO、ColIAGS、NFL-BA，见第 4 节）——内窥镜和管道是同一类场景：管状、光源贴着相机、纹理弱。
4. 在 arXiv 上没有找到把高斯泼溅 / NeRF 用于污水管、管道内部的论文（检索式见第 8 节），所以没有现成的"管道版"可以直接试；最接近的是内窥镜方向。
5. 推荐路线（第 5 节）：在 WSL2 里装 gsplat → 先在我们的位姿和几何上复现"Gaussian-LIC2 式建图"作为基线 → 加灯光模型 → 加逐帧位姿精修 → 面元几何约束 + 畸变相机 → 盲区补全 → 烘焙回网格贴图交付。
   每一步都在同一批留出帧上比较，只有前一步验收通过才做下一步。

## 1. 两个系统分别是什么

| | Gaussian-LIC2 | PipeRecon3D（我们） |
|---|---|---|
| 场景 | 户外/室内大场景，几十米深度，日光或室内灯 | 管道内部，管径 0.2–0.45 m，相机到管壁 0.1–0.5 m，唯一光源是车灯 |
| 传感器 | 激光雷达 + IMU + 相机，三者必须都有 | 视觉分支：只有视频；融合分支（InPipe）：禾赛 128 线 + RealSense + IMU + 编码器 + AprilTag |
| 位姿 | 连续时间 B 样条，激光-IMU-相机在因子图里紧耦合，实时 | 离线 SfM（内参固定、已标定畸变）；融合分支松耦合：轴向 = 编码器，横向 = 视觉 × 标记尺度，朝向 = SfM |
| 几何 | 3D 高斯，用稀疏激光深度约束（权重 γ = 0.005）；盲区用深度补全网络 SPNet 补点 | 视觉：OpenMVS 稠密点云 → 网格；融合：高度场 r(u, θ)，5 mm × 1°，逐线测距偏差自标定后管壁厚 5.1 mm |
| 外观 | 高斯的三阶球谐颜色，所有关键帧联合优化（L1 + D-SSIM） | 视觉：OpenMVS TextureMesh（每个面挑一帧）；融合：R4 逐纹素取色 + 平场 + 曝光增益；两者都可再乘灯光图（lampmap） |
| 光照 | 不建模，假设静止；曝光变化靠 D-SSIM 容忍 | 灯光图（固定在画面上的灯 × 暗角）+ 每帧增益 |
| 评测 | 序列内新视角（非训练帧）+ 序列外新视角（另一条轨迹）；PSNR / SSIM / LPIPS / 深度 L1 | 留出帧（每段 44 张）；PSNR / LPIPS / 错位 / 细节相关 / 低频、高频残差 |
| 几何精度量级 | 深度 L1 = 0.29–0.62 m（序列内，自采数据集） | 管壁局部偏差 ±1.7 mm（5–95 %），厚度 5.1 mm |

最后一行的绝对值不能直接比（户外深度几十米），但它说明：**Gaussian-LIC2 的几何是"够渲染用"的精度，不是毫米级**。所以在我们的方案里，几何的权威仍然是激光高度场 / OpenMVS 网格，高斯模型主要负责外观和配准。

## 2. 我们现在差在哪（实测）

数据来源：`lampmap/results/<数据>/summary.json`，每段 44 张没参与建模的视频帧的中位数。
B = 现有最好模型（OpenMVS 网格或 R3 高度场 + 贴图，再乘灯光图）；N = 视频自己的下一帧（带着同样的模拟视频噪声，是一个偏乐观的参照）。

| 指标 | concrete_2 B / N | 实验室管 A B / N | InPipe 172011 B / N |
|---|---|---|---|
| PSNR（dB） | 29.82 / 33.55 | 25.26 / 29.36 | 23.35 / 34.81 |
| LPIPS（越小越像） | 0.413 / 0.126 | 0.369 / 0.160 | 0.279 / 0.072 |
| 错位 shift（px）¹ | 1.33 / (1.19) | 0.61 / (1.66) | **5.13** / (0.68) |
| 细节相关 detail_corr（1–3 px 细节） | 0.37 / 0.58 | 0.47 / 0.69 | **0.07** / 0.93 |
| 细节能量比 hf_ratio（>1 表示比视频还"花"） | 1.08 / 0.92 | 1.42 / 0.95 | 1.26 / 0.99 |
| 低频残差 mse_low（6 px 以上，灯光/暗角） | 22.8 / 0.9 | 47.1 / 1.4 | **168** / 0.2 |
| 高频残差 mse_high（纹理） | 38.2 / 23.4 | 119.9 / 71.0 | 66.8 / 13.0 |
| 画面覆盖 coverage | 0.998 | 0.993 | **0.898** |

¹ N 的 shift 是相邻两帧之间真实的运动，不是误差；B 的 shift 是"同一位姿下渲染图和真实帧"的错位，是误差。

从表里直接读出四个差距（后文用 G1–G4 指代）：

- **G1 灯光与曝光（低频）**：B 的低频残差仍是参照的 26 / 34 / 880 倍。灯光图已经去掉了 80–86 %，剩下的部分对应灯光图的适用条件之外：它假设直管、相机在横截面里位置不变（lampmap/README 第 4 节）。InPipe 有 16° 弯头、两节不同管径的管子，所以剩得最多。
- **G2 配准（错位）**：InPipe 错位 5.1 px、细节相关只有 0.07，也就是贴图上的细节和视频里的细节基本对不上位置（R5 的"留出帧边缘距离 5.0 px"是同一件事）。
  视觉分支错位 0.6–1.3 px，看起来小，但 10-19 的实验已经证明它是"变清晰"的障碍：把多帧平均成贴图时，约 1 px 的逐帧误差把细节能量抹到只剩视频的 11–20 %（lampmap/README 第 5 节）。
- **G3 贴图本身**：视觉分支 hf_ratio ≈ 1.1–1.4 而 detail_corr 只有 0.37–0.47：贴图里的细节"量"够，甚至比视频多，但不是对的细节。
  原因是 TextureMesh 每个面只取一帧：那一帧的噪声、那一帧的明暗、相邻面之间的接缝都被烧进了贴图（接缝匀色因为会把 57–98 % 的面变黑而被关掉了，README 注意事项 5）。
- **G4 覆盖**：InPipe 有 10 % 的像素没有模型（高度场之外：出口之后、管底开缝里看到的地面等）；Pipe 1 管底水流处下半周只覆盖 58 %。视觉分支两段混凝土管没有这个问题。

**几何不是视觉上的首要瓶颈**：视觉分支错位约 1 px，和相邻帧的运动量同级；融合分支管壁厚 5.1 mm。所以下面的方案不去重做几何，而是把几何当作已知条件来用。

## 3. Gaussian-LIC2 逐个部件对照

| # | Gaussian-LIC2 的部件 | 在它那里解决什么 | 对应我们的差距 | 结论 |
|---|---|---|---|---|
| 1 | 3D 高斯地图，所有关键帧联合优化外观（L1 + 0.2·D-SSIM） | 照片级新视角渲染 | G3：取代"每个面只挑一帧" | **借用，但有前提**：G1、G2 不解决的话，优化器会把车灯明暗烧进高斯（ColIAGS 称之为"破坏结构的高斯"），也会像我们多帧平均那样把细节抹平 |
| 2 | 激光深度约束 + 用渲染不透明度归一化深度（式 22） | 几何准确、防止对训练视角过拟合 | 保住几何，防止 #3 漂移 | **借用并加强**：我们有逐像素的稠密几何（高度场 / 网格），比它的稀疏激光深度强。它自己的消融：去掉深度约束后光度定位在 degenerate seq 00 上从 0.03 m 漂到 7.12 m |
| 3 | 高斯地图光度相机因子 c2（式 17–18）：渲染图对原图，优化相机位姿，再进因子图 | 激光退化 + 无纹理时的定位 | **G2** | **借用，但要换损失**：它只用 D-SSIM 抵抗曝光；管道里灯光随相机移动，会把位姿往错误方向拉。NFL-BA 把光度 BA 换成近场灯光 BA 后，MonoGS、EndoGS 的相机跟踪分别改善 37 %、14 %。另外要保留先验（它的 c2 也是和激光/IMU 一起进因子图，不单独用） |
| 4 | 深度补全 SPNet：激光稀疏深度 + 图像 → 稠密深度，在激光盲区补高斯 | 激光视场外欠重建 | G4 | **后备**。它选补全而不选单目深度的理由（相对深度做最小二乘对齐后误差仍大）和我们 10-19 的实测一致：DA3/MapAnything 每帧 2 参数最优校正后近壁仍差 15–27 %。但 G4 只占 InPipe 10 % 像素、视觉分支几乎为 0，排在后面 |
| 5 | 连续时间 B 样条 + 激光-IMU-相机紧耦合里程计 | 快速运动、激光运动畸变、异步传感器 | 间接对应 G2 | **暂不做**。InPipe 机器人 146 s 走 1.73 m（平均约 1.2 cm/s），一帧激光（0.1 s）内移动约 1–2 mm，小于现在 5.1 mm 的管壁厚度；时钟/延迟 F1 已标定。直管里激光沿管轴退化，紧耦合也要靠相机来定轴向——这部分由 #3 直接提供 |
| 6 | 增量插入高斯、关闭自适应致密化（ADC）、各种 CUDA 加速 | 实时 | — | **不需要**。我们是离线处理；它关 ADC 的理由是增量建图里新旧高斯成熟度不同，离线联合优化不存在这个问题 |
| 7 | 三阶球谐（它的消融：非朗伯表面更好） | 视角相关的外观 | 部分 G1 | **作为消融项**。灯贴着相机时，视线方向 ≈ 光线方向，球谐能表达"入射角"那部分；但 1/距离² 取决于距离而不是方向，球谐表达不了——这正是必须单独建灯光模型的原因 |
| 8 | 输入去畸变后的针孔图像 | — | G3 | **改掉**。我们的镜头畸变很强（Sheffield k1 = −0.33，Pipe 1 k1 = −0.248、四角 11 % 够不到）。去畸变要重采样（会变糊）还丢四角；用 3DGUT 直接在原始畸变图像上训练（第 4 节） |
| 9 | 序列内 + 序列外两种新视角评测，训练帧不参与 | 防止只在训练视角上好看 | 评测 | **借用**。它的序列外 PSNR 比序列内低约 1.4–4.5 dB（表 5 各序列）。我们现在只有"序列内"留出帧，要加一个管道版的"序列外"测试（第 6 节） |
| 10 | 从渲染深度做 TSDF 融合再提网格 | 快速出网格 | 高度场表示不了管口端面 | **可选**，交付阶段需要端面时再用 |

**我们有、它没有的**（保留不动）：管道坐标系 (u, θ, r)；在管道里标定好的内参与畸变（沿管轴前进时焦距几乎不可观，COLMAP 自标定把模型拉长 42 %）；激光逐线测距偏差自标定（R2）；AprilTag 尺度与轴向真值；显式灯光图与曝光；针对模拟视频噪声的指标（PSNR 会奖励模糊，所以必须同时看 LPIPS 和细节相关）。

## 4. 更新、更对口的模型（2026-10-19 检索）

检索方式：WebSearch 在本机报模型错误，改用 arXiv API 和 GitHub API 直接查（检索式见第 8 节）。按"能补哪个差距"归类。

**G1 灯光（光源贴着相机、随相机移动）**

| 方法 | 做法 | 对我们的用处 | 代码 |
|---|---|---|---|
| LightNeuS（arXiv 2309.02777，MICCAI 2023） | NeuS + 标定过的内窥镜光源模型，亮度按 1/距离² 衰减 | 物理灯光模型的原型 | — |
| PR-ENDO（2411.12510，MICCAI 2025） | 高斯泼溅 + 基于物理的可重打光模型，单光源贴着相机，另加小 MLP 补复杂光效 | 和我们的成像条件最接近 | SanoScience/PR-ENDO |
| ColIAGS（2510.18739，ICME 2026） | 移动光源下的结肠镜高斯泼溅，两类衰减因子；指出不建模光照会产生"破坏结构的高斯" | 支持"不建光照就会坏几何"的判断 | haowang020110/ColIAGS |
| NFL-BA（2412.13176，v4 2026-01） | 把近场灯光写进光度 BA 损失；内窥镜和"手机开闪光灯"场景都验证 | 直接对应 G2 的光度位姿精修 | 项目页 asdunnbe.github.io/NFL-BA |
| PPISP（2601.18336，NVIDIA 2026-01） | 物理上合理的相机 ISP 补偿：曝光、暗角、白平衡、响应曲线，带新视角控制器 | 处理相机那一半（曝光、响应、暗角）；距离衰减仍要自己加 | 已集成在 gsplat（`post_processing="ppisp"`） |
| EvenSplat（2610.01876） | 图像空间光照分解 + 高斯上的光照场 | 通用不均匀光照，不针对点光源，作参考 | — |

**G2 配准**：Gaussian-LIC2 的 c2 因子；NFL-BA；GloSplat（2603.04847：联合优化位姿和外观时，把 SfM 特征轨迹作为显式锚点保留，防止纯光度优化把位姿带跑——我们有 OpenMVG 的特征轨迹）；gsplat 自带 `pose_opt`。

**G3 相机与外观**：3DGUT（2412.12507，CVPR 2025：用无迹变换投影高斯，支持任意畸变和卷帘快门，仍是光栅化速度）——已集成在 gsplat（`with_ut=True` + `radial_coeffs`）。2DGS（gsplat 有 `simple_trainer_2dgs.py`）/ PGSR / Gaussian Surfels：把高斯压成贴在表面上的面元，有法向，便于算入射角、便于贴住高度场。

**G4 盲区**：SPNet（Gaussian-LIC2 的选择）、PromptDA（2412.14015）、Prior Depth Anything（2505.10565）、Any2Full（2603.05711）——都是"图像 + 稀疏度量深度 → 稠密深度"，比 10-19 失败的单目大模型多了度量锚点。

**Gaussian-LIC2 之后的激光-相机高斯 SLAM**：LIVE-GS（2507.23273）、RMGS-SLAM（2604.12942）、LIT-GS（2606.20424，加热成像应对光照）、MIRAGE（2610.12568，用激光-IMU 给前馈视觉几何定尺度）。都是户外/大场景、静止光照，没有针对 G1–G4 的新机制，**不单独试**。
在管道退化方面有一篇激光 SLAM 的：Degeneracy-Orthogonal Geometric Constraints（2609.36753，针对轴向均匀的走廊），只在以后做在线激光里程计时有用。

**明确不采用**：
- 生成式修图（如 OneFixer 2609.32175 一类的扩散模型"修复器"）：会编造细节。管道检测要的是"还原"，编出来的裂缝或抹掉的裂缝都不可接受。
- 前馈三维大模型直接出几何（DA3、MapAnything）：10-19 已在 concrete_2 上实测失败（近壁深度被推远约 2 倍）。
- 高斯超分辨率（如 ConFi-GS 2605.24964）：没有高分辨率真值可验证，而且前提是 G2 已解决；留到主线之后再讨论。

## 5. 方案：主线六步 + 一个可选对照

**为什么用高斯（gsplat）而不是在固定网格上直接优化贴图**：两者都需要可微渲染，都要先装 CUDA 编译环境；高斯能修正网格本身的错误（OpenMVS 的飞片、接头处），能直接和 Gaussian-LIC2 的做法对比，gsplat 已带位姿优化、深度损失、畸变相机、2D 面元和 PPISP。最终交付时再把去光照的反照率烘焙回高度场/网格贴图（第 6 步），所以 OBJ 交付形式不变。

**开发和验证数据分开**：concrete_2（单传感器、位姿最可靠、迭代快）和 InPipe 172011（唯一有激光、差距最大）用来开发；实验室管 A 和 Pipe 1 在方法定型前不碰，最后原样跑一遍做独立验证。
（Pipe 1 以前没法做留出帧评测，因为 OpenMVS 贴图用了全部帧；高斯训练可以自己选训练帧，所以这次能评。）

### 第 0 步　环境（需要你批准下载和安装位置）

- 为什么：gsplat 官方预编译包最高只到 CUDA 12.4（v1.5.3，2025-07），RTX 5060 Ti（sm_120）需要 CUDA ≥ 12.8；本机 Windows 没有 nvcc 和 MSVC，所以在 WSL2 里从源码编译。
- **位置**：本机已注册的两个 WSL 发行版磁盘文件都已不存在（10-19 核实，启动报找不到 ext4.vhdx），所以在 D: 新建专用发行版 `pipe3d`。
- 下载内容、大小、安装位置和逐条命令见 [07_第0步_环境预览.md](07_第0步_环境预览.md)（合计约 8.5 GB，装在 D:）。
- 冒烟测试：gsplat 示例在 concrete_2 的 30 帧上跑通，记录显存（必须 < 8 GB）和每千次迭代用时。之后每一步的耗时都按这个实测值估算。

### 第 1 步　基线 G0：在我们的位姿和几何上复现"Gaussian-LIC2 式建图"

（具体设置、命令和事先定好的判定阈值见 [08_第1步_G0基线预览.md](08_第1步_G0基线预览.md)。）

- 做法：用我们的位姿（视觉：SfM；InPipe：融合位姿 + R2b 校正）、我们的点初始化高斯（视觉：OpenMVS 稠密点；InPipe：R1 管壁点按纹素网格下采样），尺度初值 = 深度 / 焦距（同它），三阶球谐；损失 = 0.8·L1 + 0.2·D-SSIM + 0.005·深度 L1（深度用我们的网格渲染，按渲染不透明度归一化，同它的式 22）；输入去畸变图像（同它）；不建灯光。训练帧和留出帧与 lampmap 完全相同。
- 为什么能代表 Gaussian-LIC2：原版要 Ubuntu 20.04 + ROS1 + CUDA 11.7 + TensorRT 8.6，这一套不支持本机显卡，而且只有 InPipe 有它要的传感器；它的论文自己评测建图时也是"给定位姿、只比建图"（第 9.4 节），所以这个复现和它的建图部分是同一个比较口径。
- 回答两个问题：(a) 它的建图方式在我们数据上能到多少；(b) **不建灯光行不行**。
- 判定：
  - 如果 G0 在留出帧和"整段留出"测试（第 6 节）上都不差于 lampmap 的 B → 球谐已经吸收了灯光，跳过第 2 步；
  - 如果 G0 在留出帧上好、整段留出上明显变差，或渲染深度偏离我们的几何 → 灯光被烧进了高斯，进入第 2 步。按第 3 节 #7 的分析，预计是后一种，但以实测为准。

### 第 2 步　加管内灯光模型（针对 G1）

- 做法：渲染亮度 = 每帧增益 e_t × 画面固定图 M(像素) × cos(入射角) / 距离² × 高斯的反照率（+ 每帧黑电平）。
  M 用 lampmap 学到的灯光图初始化（它就是"灯的角度分布 × 暗角"）；距离和入射角**先用我们固定的网格算**，这样本步不依赖几何是否被改动；灯相对相机的位置给 3 个参数，初值 0。相机响应、白平衡可选 PPISP。
- 预期在哪里起作用（这一点要先说清楚）：在笔直、相机居中的管段，"距离、入射角"和"像素位置"一一对应，乘起来和 M 分不开——这正是 lampmap 能用一张固定图解释的原因，所以那里预计变化不大。
  差别应该出现在 lampmap 假设不成立的地方：InPipe 0.9 m 附近的弯头、两节管径不同的管子、管节接头、相机偏离中心的帧、端盖。
- 验收：低频残差 mse_low 下降，且下降集中在上述区域（按帧位置画残差曲线来看）；整段留出测试比 G0 的落差变小。
- 不通过：如果弯头处残差不降，说明问题不在距离衰减，回头检查曝光（RealSense 自动曝光）和位姿（那就是 G2，进第 3 步）。

### 第 3 步　加逐帧位姿精修（针对 G2）

- 做法：每帧一个 6 自由度修正量，用第 2 步带灯光的渲染做光度损失来优化（Gaussian-LIC2 c2 + NFL-BA 的思路）；同时保留先验，不让位姿自由漂：
  InPipe 用融合轨迹（轴向来自编码器、AprilTag）做先验；视觉分支保留 SfM 特征轨迹的重投影约束（GloSplat 的思路）。深度约束（第 1 步就有）保留——Gaussian-LIC2 的消融说明没有它光度定位会漂。
- 顺序理由：放在第 2 步之后，因为没建模的灯光会把光度位姿拉偏（NFL-BA 的结论）；放在第 1 步之后，因为要先有一个地图才能对它配准。
- 留出帧的评测：分别报告"不修正留出帧位姿"和"冻结地图、只修正留出帧位姿"两种（后者是带位姿优化的新视角评测的常见做法，但会让数字偏乐观，所以两个都报）。
- 验收目标：InPipe 错位 5.1 → ≤ 1.5 px，视觉分支 → ≤ 0.5 px；细节相关上升。
  护栏：行程对 AprilTag 的误差（现在 −0.8 % / −0.7 %）变化不超过 0.2 个百分点；管壁厚度不变差。护栏不过就说明精修在"用位姿凑灯光"，退回加强先验。

### 第 4 步　面元几何约束 + 畸变相机（G3 的两个技术细节）

- 2DGS 面元：高斯压成贴面的小圆片，有法向（第 2 步的入射角改用它算），加深度/法向损失把它贴在高度场 / 网格上；允许在测距噪声范围内（毫米级）微调。
  要回答的问题：放开微调后几何是变好（接头、飞片）还是变坏（看管壁厚度、局部偏差图）。
- 3DGUT：直接用原始带畸变的帧训练和渲染，不再去畸变重采样。要回答的问题：画面四周的细节相关是否提高；Pipe 1 四角是否能补上（现在 11 % 留空）。
- 两项各自单独开关做对比，不一起改。

### 第 5 步　盲区补全（针对 G4，有条件）

- 只在第 1–4 步之后，"没有模型的像素"仍是残差的主要来源时才做（看残差按"有无几何覆盖"分开统计）。
- 做法：仿 Gaussian-LIC2 第 6.2 节，用"图像 + 稀疏度量深度"补全网络（SPNet / PromptDA / Any2Full 任选，先比较）在高度场之外的区域补点初始化高斯。
- 管底水流（Pipe 1）不在此列：水面在动，没有静态几何可补，按 README 已有的办法遮掉水流带。

### 第 6 步　交付

- 把去掉灯光的反照率烘焙回高度场 / 网格贴图，输出 OBJ（MeshLab/Blender 可开），同时保存高斯模型。
- 对比视频：原视频 | 旧模型 | 新模型。
- 方法定型后原样跑实验室管 A 和 Pipe 1 做独立验证；更新 README、docs；你同意的话发 `v1.1-results`（保留 v1.0 对照）。

## 6. 评测规则（先定下来，做实验时不改）

1. **序列内留出帧**：沿用 lampmap 的 44 张留出帧（数字可以和第 2 节的 B 直接比），这些帧不参与任何训练，包括地图的位姿精修。
2. **管道版"序列外"测试（新增）**：每段数据选 2 段、各约 10 cm 行程，这段内的帧全部不参与训练。
   道理：前视相机看一块管壁时，是从远看到近；整段拿掉后，这段帧里看到的近处管壁只在更远（之前的帧）和更近（之后的帧）的距离上被看过，渲染就必须外推到没见过的观察距离。
   灯光 ∝ 1/距离²，所以"把灯光烧进外观"的模型恰好会在这里露馅——相当于 Gaussian-LIC2 的序列外测试（它在那里掉 1.4–4.5 dB）。
3. 指标：PSNR、LPIPS（AlexNet）、细节相关、错位、低频/高频残差、覆盖率，并列视频下一帧 N 作参照。
   注意：模型融合了很多帧、噪声被平均掉后，PSNR 有可能超过 N（N 自己带一份噪声），所以 N 不是 PSNR 的上限；判断"清晰"主要看 LPIPS 和细节相关。
4. 几何护栏：InPipe 管壁厚度中位数（5.1 mm）和局部偏差；视觉分支渲染深度与 OpenMVS 网格的差；行程误差（AprilTag / 计数器）不变差。
5. InPipe 后视相机（`/camera/usbcam`，朝向相反）可以做真正的反向新视角测试，但需要先标它的内参和外参，列为可选。
6. 执行纪律：一次只跑一个重任务；每一步运行前把命令、输入输出、参数给你看，确认后再跑。
