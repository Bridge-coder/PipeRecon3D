# 大文件清单：模型、点云、视频（GitHub Releases）

git 仓库里只放代码、文档和小结果；带纹理的三维模型、稠密点云、稀疏模型和对比视频放在 **GitHub Releases** 的
[`v1.0-results`](https://github.com/Bridge-coder/PipeRecon3D/releases/tag/v1.0-results)（2026-10-18）。
原因：git 拒收单个超过 100 MiB 的文件（模型单个 140–376 MB），而 Releases 每个文件可到 2 GiB、总量和下载流量不限，也不会让 `git clone` 变慢。
共 16 个文件、2.01 GB，另附 `SHA256SUMS.txt`（校验值）和 `manifest.json`（每个包里的文件清单）。

原始数据集不在这里，见 [05_数据下载.md](05_数据下载.md)。


## 2. 下载与校验

```bash
gh release download v1.0-results --repo Bridge-coder/PipeRecon3D --dir D:/PipeRecon3D_release_v1.0
```

或在网页上逐个下载。Windows 下校验（与 `SHA256SUMS.txt` 对照）：

```cmd
certutil -hashfile concrete_lab.zip SHA256
```

## 3. 下载后接着用

- **只看结果**：解开 zip，用 MeshLab 打开 `mvs/scene_textured.obj`；视频直接播放（H.264）。
- **重新评估**（不需要原视频）：

  ```bash
  python scripts/vision/evaluate.py dense CONVERTER WORK/sfm/recon/sfm_data.bin WORK/frames.csv WORK/counter.csv WORK/mvs/scene_dense.ply WORK/dense_eval
  python scripts/vision/eval_gt_scale.py WORK WORK/gt_eval
  ```

  `CONVERTER` 见 `python scripts/paths.py`；`sfm_data_full.json` 会由 `sfm_data.bin` 自动重新生成。
- **重画三维视图和对比视频**：还需要抽出的帧。先按原参数重抽（只跑步骤 2，`frames.csv` 会与包里的一致），再运行 `reconstruct_video.py --skip-recon`：

  | 数据 | 步骤 2 的参数 |
  |---|---|
  | Sheffield concrete_1–5 | `--video <对应 mp4> --every 5`（默认 Sheffield 相机） |
  | Sheffield mix15_2 | `--video 300mm_mix_15meters_ON_2lm_3u_CLOSED_2_stop_at_14meters.mp4 --every 3 --last 3999` |
  | A 实验室混凝土管 | `--video 300mm_mix_15meters_ON_3lm_3u_CLOSED_1_stop_at_14meters.mp4 --every 3 --last 1350` |
  | B 真实污水管 Pipe 1 | `--video Pipe1.avi --every 1 --last 700 --plain --crop 0 0 720 490 --stretch-x 1.0159 --focal 489.7 --cx 332.4 --cy 264.5 --k1 -0.2477` |

  例如 `python scripts/vision/run_pipeline.py WORK --video VIDEO --every 3 --last 1350 2`。B 的视图和视频另外要 `PIPE3D_PIPE_DIAMETER_M=0.435` 和 `--straighten`（见 docs/02）。
- **从稀疏模型重做稠密**（改 `Densify.ini` 做优化实验时）：重抽帧后运行 `run_pipeline.py WORK 10 11 12 13`。
