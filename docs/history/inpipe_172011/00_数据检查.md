## 和 README 不一致的地方

- README 写的 2D 激光 `/scan` **不存在**；激光是 `/lidar_points`（3D 点云）。
- 包是 **MCAP** 格式（不是 README 写的 db3）。每个 zip 只有一条序列，解压后 39 GB，所以直接从 zip 流式读取，不落地解压。
- 数据集描述说"带标定信息"，但 `/tf_static` 里只有 RealSense 内部各坐标系之间的变换，**没有相机↔激光雷达、也没有车体↔传感器的外参**。
- **自带的轮式里程计 `/tf`（odom_wheels → base_link）和 `/trajectory` 是错的**：机器人只在直行（`/cmd_vel` 只有前进速度，转向为 0），
  里程计却给出 x、y 一直为 0、偏航角转过 180°。原因是左右轮编码器符号相反，里程计节点把直行算成了原地转向。

**时间戳**：激光的 header 和逐点时间戳用的是雷达自己的时钟（开机后约 1084 s），不是电脑时钟；
usbcam 的时间戳比接收时间晚约 1.0 s；RealSense 的时间戳比接收时间早约 45–110 ms。
所以跨传感器同步先统一用"接收时间"（log_time），时间偏差留到融合阶段估计。

## 场景（从图像和点云看）

- 实验室里架在木支架上的管道，**内径约 196–197 mm**（激光测得，仿真资源里也有 `pipe_200mm_5m.stl`），由几节管段对接而成。
- **管底沿纵向有一条开缝**（约 15–25° 宽），透过缝能看到下方约 0.28 m 处的地面和支架。
- 截面不是正圆：**横向约 206 mm、竖向约 185 mm**（前 0.9 m 的激光结果），是否真实变形待用视觉交叉验证。
- 开始时机器人停在管口，约 22 s 起步，速度约 0.02 m/s。
- 后视相机全程能看到管口外一块固定的 **AprilTag 36h11（编号 80）**；前视相机在远端出口外还能看到另一块标记。

## 轴向距离的参考（真值）

- 轮式编码器：轴向距离 = (v6 − v7) / 2。
- 后视 AprilTag（`scripts\tag_track.py`）：标记边长未知，按单位边长解算位姿后，与编码器拟合出的边长为 **99.9 mm**，
  即很可能是 100 mm 的标准打印尺寸。前 50 s（行程 0.44 m）里两者之差的均方根为 2.5 mm；起步阶段编码器超前约 12 mm（时间差或起步打滑）。
  → 按 100 mm 边长，后视标记可以作为**与编码器相互独立**的轴向参考。
